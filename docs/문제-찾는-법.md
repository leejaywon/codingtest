# 유형별 문제를 어디서 어떻게 가져올지

[코딩테스트 유형](./코딩테스트-유형.md)에서 공부할 알고리즘을 정한 뒤, 그 문제를 **백준(solved.ac)** 과 **리트코드**에서 찾는 방법이다.

문제 목록을 미리 다 긁어 두지 않고, 유형마다 **검색 쿼리·URL·필터**를 붙여 두었다. 이후 유형별로 문제를 가져올 때 이 문서를 인덱스로 쓰면 된다.

---

## 1. 한 줄 결론

- 백준 공식 분류보다 **solved.ac 태그 검색**이 실질적인 검색기다.
- 리트코드는 **`/tag/{slug}` 또는 `problemset/?topicSlugs=`** 가 가장 빠르다. 태그 전체보다 NeetCode 150을 먼저 가져오는 편이 낫다.
- 리트코드만 풀면 삼성·카카오식 **긴 시뮬레이션·파싱**이 약해지고, 백준만 풀면 쿠팡·토스식 **짧은 최적화 문제**가 약해진다.

| 준비 대상 | 더 잘 맞는 플랫폼 | 이유 |
| --- | --- | --- |
| 삼성, LG, 현대 등 제조·대기업 | 백준 + SWEA | 긴 구현·2차원 격자·시뮬레이션 |
| 카카오, 네이버, 라인, 배민 | 프로그래머스 + 백준 | 한국어 지문, 구현+자료구조 혼합 |
| 쿠팡, 토스, 일부 스타트업·외국계 | 리트코드 | 짧은 지문, Medium 최적화, OA 스타일 |
| 공통 기초 | 백준 실버~골드 + 리트코드 Easy~Medium | 같은 알고리즘을 두 스타일로 연습 |

카카오 계열은 프로그래머스가 사실상 본진이다. 이 문서는 백준·리트코드 찾는 법에 집중하고, 프로그래머스는 보조로만 적는다.

## 2. 백준에서 유형별 문제를 찾는 방법

백준(`acmicpc.net`) 자체에는 난이도가 없다. **분류는 백준, 난이도·검색은 solved.ac** 로 나누는 것이 정석이다.

### 2.1 공식 입구

| 목적 | URL | 쓰는 상황 |
| --- | --- | --- |
| 알고리즘 분류 전체 | https://www.acmicpc.net/problem/tags | 태그 이름을 모를 때 |
| 단계별로 풀어보기 | https://www.acmicpc.net/step | 처음 유형을 배울 때 |
| 문제 출처(대회/기업) | https://www.acmicpc.net/category | 삼성·구 정보올림피아드 등 |
| 공개 문제집 | https://www.acmicpc.net/workbook/public | 남이 모아 둔 로드맵 |
| 공식 삼성 기출 문제집 | https://www.acmicpc.net/workbook/view/1152 | 삼성 준비 필수 |
| 공식 삼성 A형 기출 | https://www.acmicpc.net/workbook/view/2771 | A형 위주 |

백준 분류 페이지에서 태그를 누르면 `https://www.acmicpc.net/problemset?algo={번호}` 형태의 목록이 열린다. 번호는 UI에서 클릭해 확인하는 편이 안전하다. 검색·난이도 필터는 백준보다 solved.ac가 강력하다.

### 2.2 solved.ac가 실질적인 검색기인 이유

solved.ac는 백준 문제에 **커뮤니티 난이도(브론즈~루비)** 와 **알고리즘 태그** 를 붙인다.

- 태그 목록: https://solved.ac/problems/tags
- 고급 검색: https://solved.ac/search
- CLASS(단계 추천): https://solved.ac/class
- 검색 도움: https://help.solved.ac/ko/problem/tag

태그 ID는 `#` 뒤에 붙는 영문 슬러그다. 예: 다이나믹 프로그래밍 → `#dp`.

### 2.3 고급 검색 문법 (핵심만)

검색창 또는 `https://solved.ac/search?query=` 뒤에 그대로 넣는다. 공백은 AND.

| 문법 | 의미 | 예시 |
| --- | --- | --- |
| `#태그` | 해당 태그 | `#bfs` |
| `#a #b` | AND | `#bfs #simulation` |
| `#a \| #b` | OR | `#bfs \| #dfs` |
| `-#태그` | 제외 | `#dp -#math` |
| `*티어` / `*a..b` | 난이도 | `*g5..g1`, `*s2..g4` |
| `s#n..` | 푼 사람 수 | `s#5000..` (검증된 문제) |
| `id:a..b` | 문제 번호 | `id:1000..1999` |
| `/출처` | 대회·출처 | `/smupc` 등 |
| `%ko` | 한국어 문제 | `%ko` |
| `@핸들` | 그 유저가 푼 문제 | `@myid` |
| `-@핸들` | 안 푼 문제 | `-@myid` |
| `c/3` | CLASS 3 | `c/3` |
| `o?true` | 지금 풀 수 있는 문제 | `o?true` |

티어 약어: `b` 브론즈, `s` 실버, `g` 골드, `p` 플래티넘, `d` 다이아, `r` 루비. `g5` = 골드 5, `g1` = 골드 1.

### 2.4 코테용으로 바로 쓰는 검색 레시피

브라우저 검색창에 붙여 넣으면 된다. `{id}` 는 본인 solved.ac 핸들.

```text
# 골드 코테 핵심: 많이 풀린 BFS
#bfs *g5..g1 s#2000.. %ko

# 삼성형: 시뮬레이션 + 그래프 탐색
#simulation #bfs *g5..g1 s#1000..

# 구현만, 수학·기하 제외
#implementation *s1..g3 s#3000.. -#math -#geometry

# 파라메트릭 서치
#binary_search *g5..g2 s#1500..

# 내가 안 푼 실버 DP
#dp *s5..s1 -@{id}

# CLASS 3 에센셜
e/3
```

코테 연습은 **푼 사람이 많은 문제부터** 보는 것이 맞다. `s#` 를 크게 잡으면 지문 오류·마이너 대회 문제가 걸러진다.

추천 난이도 밴드:

| 단계 | solved.ac 쿼리 밴드 | 목적 |
| --- | --- | --- |
| 유형 입문 | `*s5..s2` | 템플릿 고정 |
| 국내 코테 본진 | `*s1..g3` | 대부분의 1차 |
| 네카라쿠배·삼성 | `*g4..g1` | 변별 문제 |
| 과한 구간 | `*p5..` | 일반 신입 코테에선 후순위 |

### 2.5 API로 목록을 가져오는 방법

solved.ac는 공개 API가 있다. 브라우저 검색과 같은 `query` 를 쓴다.

```text
https://solved.ac/api/v3/search/problem?query=%23bfs%20*g5..g1&sort=solved&direction=desc&page=1
```

| 파라미터 | 의미 |
| --- | --- |
| `query` | 고급 검색 문자열. `#` 는 URL 인코딩 `%23` |
| `sort` | `solved`, `level`, `id`, `average_try` 등 |
| `direction` | `asc` / `desc` |
| `page` | 페이지 |

태그 목록:

```text
https://solved.ac/api/v3/tag/list
```

주의: 엔드포인트가 Cloudflare 뒤에 있어, 스크립트에서는 User-Agent·재시도가 필요할 수 있다. 대량 크롤링은 이용약관·요청 간격을 지켜야 한다.

응답의 `items[].problemId` 가 백준 번호다. 문제 페이지는 `https://www.acmicpc.net/problem/{id}` .

### 2.6 이미 잘 모아 둔 문제집

| 이름 | URL | 용도 |
| --- | --- | --- |
| 백준 공식 삼성 기출 | https://www.acmicpc.net/workbook/view/1152 | 삼성 1순위 |
| 삼성 A형 기출 | https://www.acmicpc.net/workbook/view/2771 | A형 |
| tony9402 추천 문제 | https://github.com/tony9402/baekjoon | 태그별 추천/연습 분리 |
| solved.ac CLASS | https://solved.ac/class | 난이도 계단 |
| 단계별로 풀어보기 | https://www.acmicpc.net/step | 공식 커리큘럼 |

tony9402 저장소는 폴더가 solved.ac 태그 슬러그와 맞다. `graph_traversal`, `two_pointer`, `disjoint_set` 처럼 들어가서 `list.md` 를 보면 된다.

## 3. 리트코드에서 유형별 문제를 찾는 방법

리트코드는 **토픽 태그(slug)** 가 검색 키다. 한국어 기업 기출 태그는 거의 없고, 알고리즘 패턴·미국 기업 태그 위주다.

### 3.1 브라우저에서 찾는 세 가지 길

**1) 태그 페이지**

```text
https://leetcode.com/tag/{slug}/
```

예: https://leetcode.com/tag/dynamic-programming/

**2) 문제 목록 + 필터 (추천)**

```text
https://leetcode.com/problemset/?topicSlugs={slug}
https://leetcode.com/problemset/?difficulty=MEDIUM&topicSlugs=breadth-first-search
```

여러 태그는 쉼표:

```text
https://leetcode.com/problemset/?topicSlugs=graph,breadth-first-search
```

**3) 사이트 검색**

문제 목록 상단 검색창에 `island`, `course schedule` 처럼 패턴 키워드를 넣는다. 유형보다 **대표 문제 이름** 을 알 때 유용하다.

### 3.2 코테에 쓰는 공식 태그 슬러그

| 보고 싶은 유형 | LeetCode `topicSlugs` / `/tag/` |
| --- | --- |
| 배열 | `array` |
| 문자열 | `string` |
| 해시 | `hash-table` |
| 구현/시뮬 | `simulation` |
| 행렬/격자 | `matrix` |
| 완전탐색 | `enumeration`, `backtracking` |
| DFS | `depth-first-search` |
| BFS | `breadth-first-search` |
| 그래프 | `graph` |
| 트리 | `tree`, `binary-tree` |
| 이분탐색 | `binary-search` |
| 투포인터 | `two-pointers` |
| 슬라이딩 윈도우 | `sliding-window` |
| 누적합 | `prefix-sum` |
| 스택 | `stack`, `monotonic-stack` |
| 큐 | `queue`, `monotonic-queue` |
| 힙 | `heap-priority-queue` |
| 정렬 | `sorting` |
| 그리디 | `greedy` |
| DP | `dynamic-programming` |
| 비트 | `bit-manipulation`, `bitmask` |
| 유니온 파인드 | `union-find` |
| 위상정렬 | `topological-sort` |
| 최단경로 | `shortest-path` |
| 트라이 | `trie` |
| 연결리스트 | `linked-list` |
| 구간 | 별도 태그 약함. `array` + `sorting` + 직접 선별 |
| MST | `minimum-spanning-tree` (문제 수 적음) |

난이도 필터 값: `EASY`, `MEDIUM`, `HARD`.

국내 코테 연습은 **Easy로 템플릿 → Medium을 본진** 으로 두면 된다. Hard는 토스·외국계·여유 있을 때.

### 3.3 이미 잘 고른 리스트

리트코드 전체를 태그로 훑으면 문제가 너무 많다. 패턴 학습은 큐레이션이 더 낫다.

| 리스트 | URL | 메모 |
| --- | --- | --- |
| NeetCode Roadmap | https://neetcode.io/practice | 유형별 순서. 사실상 표준 |
| NeetCode 150 (LC 리스트) | https://leetcode.com/problem-list/plakya4j/ | 계정에 저장해 두고 풀기 |
| Blind 75 | NeetCode 사이트 탭 | 더 짧은 핵심 |
| LeetCode Explore / Study Plan | https://leetcode.com/explore/ | 공식 토픽 플랜 |
| 회사별 기출 덤프 | https://github.com/liquidslr/leetcode-company-wise-problems | Premium 회사 태그 미러. 쿠팡 등 |

회사 태그(`Google`, `Coupang` 등)는 리트코드 Premium 기능이다. 무료로 보려면 위 GitHub CSV(30/60/90일, all-time)를 쓰면 된다. 한국 대기업 기출의 정확한 미러는 아니다.

### 3.4 GraphQL로 목록을 가져오는 방법

공식 REST 목록 API는 없고, 웹이 쓰는 GraphQL이 있다.

- 엔드포인트: `POST https://leetcode.com/graphql`
- 필터 예: `filters.tags` 에 슬러그 배열

개념적인 요청 형태:

```graphql
query problemsetQuestionList($categorySlug: String, $limit: Int, $skip: Int, $filters: QuestionListFilterInput) {
  problemsetQuestionList: questionList(
    categorySlug: $categorySlug
    limit: $limit
    skip: $skip
    filters: $filters
  ) {
    total: totalNum
    questions: data {
      frontendQuestionId: questionFrontendId
      title
      titleSlug
      difficulty
      paidOnly: isPaidOnly
      acRate
      topicTags { name slug }
    }
  }
}
```

변수 예:

```json
{
  "categorySlug": "",
  "skip": 0,
  "limit": 50,
  "filters": {
    "difficulty": "MEDIUM",
    "tags": ["breadth-first-search", "graph"]
  }
}
```

문제 URL: `https://leetcode.com/problems/{titleSlug}/`

주의:

- 스키마·쿼리 이름이 가끔 바뀐다.
- `paidOnly: true` 는 Premium. 코테 연습 목록에서는 빼는 것을 권장.
- 비공식 스크래핑은 약관·차단 위험이 있다. 소량·학습 목적이면 태그 URL을 손으로 쓰는 편이 안전하다.

### 3.5 리트코드에서 한국 코테 유형이 비는 지점

리트코드에 **없거나 빈약한** 유형은 백준으로 보완한다.

| 한국 코테 유형 | 리트코드로 충분한가 | 보완 |
| --- | --- | --- |
| 긴 시뮬레이션 (뱀, 상어, 원판) | 부족. `simulation` 은 짧은 문제 위주 | 백준 삼성 기출 문제집 |
| 카카오형 장문 파싱 | 부족 | 프로그래머스 카카오 기출 |
| 상태 BFS (열쇠, 벽 부수기) | 일부 있음 | 백준 `#bfs *g4..g1` |
| 파라메트릭 + 판정함수 | 이분탐색 Medium으로 일부 | 백준 `#binary_search *g` |
| 일반 트리 + 트리 DP | 이진 트리에 편중 | 백준 `#trees *g` |
| SQL | `database` 태그로 충분 | 별도 |

## 4. 유형 ↔ 검색 키 매핑표

같은 유형을 두 플랫폼에서 찾을 때 쓰는 **정확한 키** 다. 백준 칸의 쿼리는 solved.ac 검색창에 그대로 넣는다.

solved.ac 검색 URL 형태:

```text
https://solved.ac/search?query=%23bfs%20*g5..g1%20s%232000..
```

리트코드 필터 URL 형태:

```text
https://leetcode.com/problemset/?difficulty=MEDIUM&topicSlugs=breadth-first-search
```

### 4.1 1순위

| 유형 | solved.ac 쿼리 | LeetCode 태그 URL |
| --- | --- | --- |
| 구현 | `#implementation *s1..g3 s#2000..` | [simulation](https://leetcode.com/tag/simulation/) · [matrix](https://leetcode.com/tag/matrix/) |
| 시뮬레이션 | `#simulation *g5..g1 s#1000..` | [simulation](https://leetcode.com/tag/simulation/) |
| 완전탐색 | `#bruteforcing *s2..g4 s#2000..` | [backtracking](https://leetcode.com/tag/backtracking/) · [enumeration](https://leetcode.com/tag/enumeration/) |
| BFS | `#bfs *s1..g2 s#2000..` | [breadth-first-search](https://leetcode.com/tag/breadth-first-search/) |
| DFS | `#dfs *s1..g3 s#2000..` | [depth-first-search](https://leetcode.com/tag/depth-first-search/) |
| 그래프 탐색 전반 | `#graph_traversal *s1..g3` | [graph](https://leetcode.com/tag/graph/) |

### 4.2 2순위

| 유형 | solved.ac 쿼리 | LeetCode 태그 URL |
| --- | --- | --- |
| 투포인터 | `#two_pointer *s2..g3` | [two-pointers](https://leetcode.com/tag/two-pointers/) |

## 6. 같은 알고리즘인데 플랫폼마다 문제가 다른 이유

나중에 문제를 자동으로 모을 때 헷갈리기 쉬운 지점이다.

1. **태그는 “가장 쉬운 정해” 기준** 이다. solved.ac 가이드상 여러 풀이가 있으면 태그가 넓게 붙기도 한다. `#dp #bfs` 가 동시에 달린 문제는 “순수 DP 연습”용으로 부적절할 수 있다. 입문 단계에서는 태그 하나 + 푼 사람 수로 좁힌다.
2. **리트코드 `graph` 와 백준 `#graphs`** 는 범위가 다르다. 리트코드 graph는 인접 리스트/격자 탐색 중심, 백준 `#graphs` 는 이론·최단경로·플로우까지 포함한다. 코테용 탐색은 백준에서 `#graph_traversal`, `#bfs`, `#dfs` 가 더 맞다.
3. **파라메트릭 서치** 는 리트코드에서 대부분 `binary-search` 에 섞여 있다. 백준도 `#binary_search` 아래 있다. 별도 태그 `parametric_search` 가 있으면 그걸 우선한다.
4. **슬라이딩 윈도우** 는 리트코드 태그가 뚜렷하고, 백준은 `#two_pointer` 에 많이 흡수되어 있다.
5. **Premium 문제** 는 목록에서 빼야 실습이 가능하다. GraphQL의 `paidOnly` 또는 페이지의 자물쇠.
6. **한국어 지문** 이 필요하면 solved.ac에 `%ko` 를 붙인다. 리트코드는 영문(한국어 번역이 있어도 설명이 짧은 편).

## 7. 문제를 모을 때 쓸 실무 절차

### 백준 세트

1. 아래 4장의 쿼리를 고른다.
2. solved.ac 검색 또는 `GET /api/v3/search/problem` 으로 목록을 받는다.
3. `sort=solved`, `direction=desc` 로 많이 풀린 순.
4. 상위 10~20개를 고른다. 입문용은 `*s`, 실전용은 `*g`.
5. 문제 번호로 `https://www.acmicpc.net/problem/{id}` 에 연결한다.
6. 삼성만 별도로 workbook 1152/2771 을 통째로 넣는다.

### 리트코드 세트

1. 같은 유형의 slug 로 `/tag/{slug}` 또는 `topicSlugs` 를 연다.
2. 가능하면 NeetCode 150에서 해당 카테고리를 먼저 가져온다. 품질이 태그 전체보다 안정적이다.
3. 부족하면 Medium + 높은 acceptance + non-premium 으로 보충한다.
4. 한국 시뮬/파싱이 필요하면 여기서 억지로 채우지 말고 백준으로 넘어간다.

### 양쪽 다 있을 때

- **개념 학습**: 리트코드 (지문 짧음, 패턴 명확).
- **실전 체력**: 백준 (입력 파싱, 엣지, 긴 구현).
- **한국어 기업 기출**: 프로그래머스 → 백준 기출 문제집 → 리트코드 순.
