# 운영 · 배포

사이트 화면에는 나오지 않는 설정입니다. 배포는 직접 하면 됩니다.

## 구성

Vercel(프론트) + Supabase(로그인·DB) + 브라우저 Python 실행.

## Supabase

1. 무료 프로젝트를 만듭니다.
2. SQL Editor에 `0001_init.sql` 다음 `0002_nickname_auto_lock.sql` 다음 `0003_service_role_grants.sql`, `0004_keep_solve_history.sql`, `0005_concept_notes.sql` 순서로 실행합니다.
3. Authentication → Providers에서 Google만 켭니다. Email 로그인은 끕니다.
4. Google Cloud OAuth 클라이언트(웹):
   - 자바스크립트 원본: `http://127.0.0.1:5173`, `http://localhost:5173`, `https://codingtest.org`
   - 리디렉션 URI: `https://<PROJECT>.supabase.co/auth/v1/callback`
5. Authentication → URL Configuration
   - Site URL: 로컬은 `http://127.0.0.1:5173`, 배포 후 `https://codingtest.org`
   - Redirect URLs: `http://127.0.0.1:5173/**`, `http://localhost:5173/**`, `https://codingtest.org/**`, `https://www.codingtest.org/**`
6. 루트 `.env`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. service role은 프론트/Vercel에 넣지 않습니다.

## 로컬

```bash
./scripts/import-problems.sh --limit 8 --supabase
./scripts/dev.sh
```

이미 SQLite에 문제가 있으면 `./scripts/push-supabase.sh`만 실행합니다. 공개 예제만 추가·갱신하며, 기존 문제와 제출 기록은 지우지 않습니다. 문제를 SQL에서 삭제하면 그 문제의 제출만 함께 지워집니다. 히든 테스트는 올리지 않습니다. 앱은 http://127.0.0.1:5173

## Vercel + codingtest.org

Hobby는 개인/비상업입니다.

1. Root Directory는 `frontend`. Build `npm run build`, Output `dist`, Install `npm ci`. `frontend/vercel.json`이 SPA 라우팅을 담당합니다.
2. Environment Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (Production/Preview).
3. Domains에 `codingtest.org`, `www.codingtest.org`.
4. Dynadot DNS에 Vercel이 준 A/CNAME만 넣습니다. 도메인 이전은 하지 않습니다.
5. 주 주소를 정하고 나머지는 리다이렉트. HTTPS는 DNS 확인 후 Vercel이 발급합니다.
6. Supabase Auth URL과 Google OAuth 원본을 `https://codingtest.org`로 맞춥니다.

## 문제 카탈로그

`backend/catalog/seed.json`에 가져올 문제 ID. 유형은 `docs/코딩테스트-유형.md`.

## Concepts 필기

기존 프로젝트는 Supabase SQL Editor에서 `supabase/migrations/0005_concept_notes.sql`을 한 번 실행한 뒤 프론트를 배포합니다. 사용자별 필기는 `concept_notes`에 저장되며 로그인 사용자가 읽을 수 있고, 작성자만 생성·수정할 수 있습니다. 닉네임과 사진은 기존 `profiles`에서 가져옵니다. 기본 설명은 코드에 그대로 보존됩니다.

Save 전 초안은 현재 탭의 sessionStorage에 사용자·개념별로 보관하며, 같은 개념에서 연필을 누르면 복구됩니다. Cancel은 해당 초안을 버립니다. Save한 내용은 다른 로그인 사용자가 프로필을 눌러 읽을 수 있습니다. 동시 수정 충돌 시 저장을 거절하고 작성 내용을 유지합니다.
