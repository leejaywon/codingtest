# 코딩테스트에서 공부할 유형

한국 대기업·스타트업 코딩테스트에서 **자주 나오는 유형**과, 빈도는 낮아도 **꼭 짚고 넘어가야 하는 유형**을 정리한다.

기준 시점: 2025~2026년 공개 후기·기출 분석. 실제 출제는 공고·연도·직군마다 달라진다.

---

## 1. 한 줄 결론

- 중심은 **구현 + 완전탐색 + DFS/BFS** 이다.
- 그다음으로 **해시, 문자열, 그리디, 이분탐색, 힙/스택/큐, DP** 가 점수를 가른다.
- **2순위까지**가 “꼭 짚고 넘어갈” 선이다. 3순위는 목표 기업이 정해진 뒤에 얹는다.

---

## 2. 자주 나오는 유형 (1순위)

코테에서 **거의 매 시즌 한 번은 보는** 유형이다. 여기가 흔들리면 다른 걸 알아도 점수가 안 나온다.

### 2.1 구현 · 시뮬레이션

- **무엇**: 규칙을 코드로 옮기는 능력. 알고리즘 이름은 없어도 조건이 길고, 격자·방향·턴·객체 상태가 많다.
- **하위 패턴**
  - 2차원 배열 이동, 회전, 반전, 테두리 복사
  - 방향 배열 `dx, dy`, 시계/반시계
  - 주사위·톱니바퀴·컨베이어처럼 상태 기계
  - 매 초/턴마다 여러 객체를 동시에 갱신
  - 조건 분기가 많은 케이스워크
- **실전 포인트**: 알고리즘보다 **인덱스, 복사 vs 제자리 갱신, 경계, 동시성(임시 맵)** 에서 틀린다.

### 2.2 완전탐색 · 백트래킹

- **무엇**: 가능한 경우를 다 보거나, 가지치며 탐색.
- **하위 패턴**
  - 순열/조합/부분집합 (`itertools` 또는 재귀)
  - N-Queen, 연산자 끼워넣기, 치킨 배달형 “위치 고르기”
  - 비트마스크로 상태 압축한 완전탐색
  - 탐색으로 후보를 고른 뒤 시뮬레이션
- **실전 포인트**: 시간복잡도 계산이 먼저다. `N!`, `2^N`, `N^2 * 4^K` 를 시험장에서 바로 쓸 수 있어야 한다.

### 2.3 그래프 탐색 (DFS / BFS)

- **무엇**: 연결, 영역, 최단 칸 수, 퍼짐, 상태 전이.
- **하위 패턴**
  - 격자 BFS (미로, 토마토, 빙산, 섬)
  - 연결 요소, 단지 번호, 영역 넓이
  - 0-1 BFS, 가중치 없는 최단거리
  - 상태 BFS (열쇠 보유, 벽 부순 횟수, 말처럼 이동)
  - 그래프 DFS (사이클, 경로 존재, 트리 부모)
- **실전 포인트**: “그래프가 안 보이면” 상태를 정점으로 바꿔라. `(r, c, keyMask)` 같은 확장이 골드 코테의 핵심이다.

### 2.4 해시 · 맵 · 셋

- **무엇**: O(1)~O(log N) 조회. 빈도, 존재 여부, 그룹핑.
- **하위 패턴**
  - 두 수의 합, 의상 조합, 베스트앨범
  - 좌표 압축, (x, y) 방문 체크
  - 문자열 키, 멀티셋, 카운터
  - “이전에 본 값”을 저장해 한 번에 답 내기
- **실전 포인트**: 파이썬 `dict`/`set`, 자바 `HashMap`/`HashSet` 만 잘 써도 한 문제는 풀린다.

### 2.5 문자열 처리 · 파싱

- **무엇**: 긴 규칙, 파일명 정렬, 압축, 수식, 캐시, 오픈채팅처럼 문자열을 해석하고 가공하는 문제.
- **하위 패턴**
  - split/정규식, 토큰화
  - 괄호 검증, 스택과 함께
  - 접두사/접미사, 부분문자열
  - 구현형 파싱 + 자료구조
- **실전 포인트**: 알고리즘 태그보다 **예외 케이스·출력 형식** 이 많다. 짧은 문자열 문제만 풀면 장문 파싱이 안 잡힌다.

### 2.6 정렬 · 그리디

- **무엇**: 기준을 정해 정렬한 뒤 앞에서부터 확정.
- **하위 패턴**
  - 커스텀 정렬 (다중 키)
  - 회의실, 택배, 주유소, 배낭이 아닌 탐욕
  - 우선순위 큐와 결합한 스케줄링
  - 구간 덮기, 최소 횟수
- **실전 포인트**: “탐욕이 되는 이유”를 한 줄로 말할 수 있어야 한다. 안 되면 DP/탐색이다.

### 2.7 이분탐색 · 파라메트릭 서치

- **무엇**: 정렬된 위치 찾기, 또는 **조건을 만족하는 최솟값/최댓값** 을 이분탐색.
- **하위 패턴**
  - `lower_bound` / `upper_bound`
  - 나무 자르기, 랜선, 징검다리 — “결정 문제로 바꾸기”
  - 이분탐색 + BFS/그리디 판정함수
- **실전 포인트**: 탐색 대상이 인덱스가 아니라 **정답 후보다**. `mid`가 가능한지 `check(mid)` 로 판정한다.

### 2.8 스택 · 큐 · 덱 · 힙

- **무엇**: 순서와 우선순위.
- **하위 패턴**
  - 괄호, 오큰수, 히스토그램 (스택)
  - 기능개발, 프린터, 카드 (큐)
  - 슬라이딩 윈도우 최댓값 (덱)
  - 더 맵게, 디스크 컨트롤러, 중간값 (힙)
- **실전 포인트**: 자료구조 자체보다 **언제 push/pop 하는지** 가 문제다.

### 2.9 동적 계획법 (기초~중급)

- **무엇**: 부분 문제의 답을 저장해 중복을 없앤다. 단기간에 올리기 가장 어렵다.
- **코테에서 실제로 필요한 DP**
  - 1차원: 타일, 계단, 식량, 피보나치형
  - 2차원: 격자 경로, LCS, 배낭
  - LIS (최장 증가 수열)
  - 구간 DP 입문 (파일 합치기)
- **실전 포인트**: 점화식보다 **상태 정의** 가 먼저다. `dp[i] = i까지 봤을 때 ~` 를 말로 쓸 수 있어야 한다.

## 3. 빈도는 낮아도 꼭 짚고 넘어갈 유형 (2순위)

매 시험마다 나오지는 않는다. 다만 **한 문제 나오면 변별력이 되고**, 모르면 그 칸을 버린다.

### 3.1 투포인터 · 슬라이딩 윈도우

- 정렬된 두 포인터, 부분합이 S 되는 최소 길이, 중복 없는 최장 부분문자열.
- 누적합과 같이 보면 좋다.

### 3.2 누적합 · 차분

- 구간 합 O(1), 2차원 누적합, imos법(차분 배열).
- 구현 문제에 섞이면 시간초과를 막아 준다.

### 3.3 최단경로 (다익스트라, 플로이드)

- 양의 가중치: 다익스트라 + 힙.
- 모든 쌍: 플로이드-워셜 (`N <= 400` 감각).
- 경유 최단경로, 택시 합승, 배달형.
- 벨만-포드는 코테에서 드물다. “음수 간선”만 개념으로.

### 3.4 트리

- 부모 찾기, 지름, DFS 트리, 레벨, 이진 트리 순회.
- 국내 코테는 **일반 트리 + BFS/DFS** 가 더 흔하고, 리트코드는 이진 트리 비중이 크다.
- 트리 DP, LCA는 3순위에 가깝다. “트리에서 DP” 한 문제는 간헐적으로 나온다.

### 3.5 위상정렬

- 선수과목, 게임 개발, 줄 세우기.
- 그래프 + 큐. 사이클 검출과 같이 익힌다.

### 3.6 유니온 파인드 (분리 집합)

- 연결 여부, 사이클, 네트워크 연결.
- 구현이 짧아 가성비가 좋다. 경로 압축 + union by rank.

### 3.7 비트마스크

- 방문 상태를 정수로 압축, 부분집합 enumeration.
- `1<<N` (`N<=20`) 감각.
- 비트 연산 (`& | ^ <<`) 자체는 구현 도구다. TSP·상태 DP의 재료이지, TSP와 같은 유형은 아니다.

### 3.8 TSP (외판원 순회 · 비트 DP)

- **무엇**: 모든 정점을 한 번씩 방문하고 (보통) 출발점으로 돌아오는 최소 비용. 코테에서는 순수 TSP보다 **해밀턴 경로/모든 곳 방문 최단** 변형이 더 많다.
- **왜 2순위**: 매 시험 나오지는 않는다. 다만 `N<=16` 완전탐색이 시간 초과 나는 순간 정해는 거의 항상 `dp[mask][v]` 다.
- **하위 패턴**
  - 순열 완전탐색: `N<=10`
  - Held-Karp 비트 DP: `dp[visited][here]`, `N<=16`
  - 돌아오지 않는 해밀턴 경로, 시작점 자유
  - “모든 노드 방문” 격자/그래프 BFS + 비트마스크
- **실전 포인트**: 복잡도 `O(2^N * N^2)` 를 바로 쓸 수 있어야 한다. 비트마스크(3.7)를 먼저 익힌 뒤 이 유형을 본다.

### 3.9 트라이 (Trie)

- 전화번호 목록, 자동완성, 가사 검색.
- 빈도는 낮지만 **나오면 대체 풀이가 없다**.
- 해시로 때울 수 있는지도 같이 본다.

### 3.10 조합론 · 순열조합 구현

- nCr, 모듈러, 중복 순열, 같은 것이 있는 순열.
- 완전탐색의 재료. 수학 문제를 따로 내기보다 탐색에 붙는다.

### 3.11 MST (크루스칼 / 프림)

- 최소 연결 비용. 유니온 파인드와 세트.
- 빈도는 다익스트라보다 낮다. 개념·한 문제면 충분.

### 3.12 그리디 + 자료구조 혼합

- 순수 그리디보다 **정렬 + 힙**, **그리디 + 이분탐색** 이 실제 코테형이다.

### 3.13 재귀 · 분할정복

- 쿼드트리, 색종이, 행렬 곱셈, 병합 정렬 느낌의 분할.
- 압축, 분할 격자.

## 4. 알아 두면 좋지만 일반 코테 후순위 (3순위)

일반 신입 코테에서 **안 나와도 이상하지 않은** 것들이다. 삼성 B/C형, 경력, PS 대회, 일부 상향 평준화 전형이 아니면 깊게 팔 필요는 없다.

| 유형                                     | 언제 필요한가         | 코테 조언                 |
| ---------------------------------------- | --------------------- | ------------------------- |
| 세그먼트 트리, 펜윅, 레이지 프로파게이션 | 삼성 B형, 쿼리 최적화 | A형·일반 코테는 스킵 가능 |
| KMP, 라빈카프, Z, 아호코라식             | 특수 문자열           | 해시/트라이로 대부분 대체 |
| SCC, 2-SAT                               | 드묾                  | 개념만                    |
| 네트워크 플로우, 이분 매칭               | 거의 안 나옴          | 스킵                      |
| 볼록 껍질, 선분 교차                     | 기하 한 문제          | CCW 정도만                |
| 게임 이론 (님, 그런디)                   | 매우 드묾             | 스킵                      |
| 퍼시스턴트 세그, HLD, 센트로이드         | 대회용                | 코테 범위 밖              |
| SQL, 설계, API                           | 일부 전형             | 알고리즘 문서 밖          |

## 5. 유형별 공부 체크리스트

각 유형을 “할 줄 안다”고 말하려면 아래를 빈칸 없이 구현할 수 있어야 한다.

| 유형          | 손에 익혀 둘 템플릿                        |
| ------------- | ------------------------------------------ |
| 구현          | 방향 배열, 90도 회전, 범위 체크, 깊은 복사 |
| 완전탐색      | 순열/조합 재귀, 방문 배열, 가지치기        |
| DFS           | 재귀 DFS, 스택 DFS, 연결 요소              |
| BFS           | 큐 BFS, 거리 배열, 다중 시작점, 상태 BFS   |
| 해시          | 빈도 맵, 존재 셋, 그룹핑                   |
| 문자열        | split, 스택 파싱, 대소문자·숫자 토큰       |
| 그리디        | 커스텀 정렬, 구간 탐욕                     |
| 이분탐색      | 인덱스 이분, 파라메트릭 `check`            |
| 스택/큐/힙    | 오큰수, 우선순위 큐 top-k                  |
| DP            | 1차원, 2차원 격자, 배낭, LIS               |
| 투포인터      | 정렬 투포인터, 가변 윈도우                 |
| 누적합        | 1차원, 2차원                               |
| 다익스트라    | 힙 + 거리 배열, 경로 복원                  |
| 플로이드      | 3중 루프, 경유 해석                        |
| 트리          | 인접리스트, 부모/깊이, 지름 2회 BFS        |
| 위상정렬      | 진입차수 + 큐, 사이클이면 불가능           |
| 유니온 파인드 | find/union, 경로 압축                      |
| 비트마스크    | 켜기/끄기/토글, 부분집합                   |
| TSP           | `dp[mask][v]`, `O(2^N N^2)`, N<=10은 순열  |
| 트라이        | insert/search/prefix                       |
| MST           | 크루스칼 + UF                              |

## 6. 기업군별 출제 성향

유형을 먼저 익힌 뒤, 목표 기업에 맞춰 비중만 조절하면 된다. 아래는 2024~2026년 공개 후기·공고 기준이다. 같은 그룹이라도 **계열사·직무·기수마다 전형이 갈린다.**

### 6.1 대기업·네카라쿠배

| 기업/군            | 전형 느낌                      | 잘 나오는 것                              | 덜 나오지만 대비할 것                        |
| ------------------ | ------------------------------ | ----------------------------------------- | -------------------------------------------- |
| 삼성 SW 역량테스트 | 3~4시간 2문제, 빡구현          | 2차원 배열, 시뮬레이션, DFS/BFS, 완전탐색 | 다익스트라, 간단한 DP. B형은 자료구조·최적화 |
| 카카오             | 다문항·장시간, 정확성+효율성   | 문자열/파싱, 구현, 해시, 그래프, 이분탐색 | 트라이, 비트마스크, 트리 DP                  |
| 네이버             | 2~3문제 / 약 2시간             | 구현, 탐색, 자료구조, DP 혼합             | 과제·API 설계가 같이 나오기도 함             |
| 라인               | 구현 비중 높음                 | 문자열, 자료구조, BFS, 시뮬레이션         | 시스템 설계는 경력 위주                      |
| 쿠팡               | Codility/리트코드형, 시간 짧음 | 배열, 해시, 이분탐색, 그리디, 그래프      | 위상정렬, 트리 DP                            |

### 6.2 SK · LG · 통신사 (최근)

네카라쿠배·삼성만큼 유형이 고정되어 있지 않다. 공통점은 **구현 + 그래프 탐색** 이고, 최근에는 **전통 코테를 줄이거나 AI 활용 전형으로 바꾸는** 곳이 생겼다.

### 6.3 스타트업

스타트업은 회사마다 편차가 크지만, 대체로 아래 둘 중 하나다.

1. **프로그래머스 레벨 2~3** — 해시, 구현, 스택/큐, BFS, 정렬, 그리디
2. **리트코드 Easy~Medium OA** — Two Sum류 해시, 슬라이딩 윈도우, 이진 탐색, 그래프 한 문제

시니어·플랫폼 직군으로 갈수록 DP·그래프·설계가 붙고, 주니어·서비스 직군은 구현·자료구조로 끝나는 경우가 많다.

### 6.5 기업별 유형 비중

- **삼성**: 1순위의 구현·완전탐색·BFS가 거의 전부다. 긴 시뮬레이션에 시간을 더 쓴다.
- **카카오**: 문자열·파싱·해시 비중이 높다. 2순위의 트라이·비트마스크·TSP가 간헐적으로 변별이 된다.
- **네이버·라인·배민**: 1순위 혼합. 극단적 빡구현이나 극단적 최적화보다는 표준 그래프·구현.
- **쿠팡·토스**: 이분탐색·DP·그래프 최적화가 더 중요하다. 위상정렬·TSP는 나오면 그 칸을 가르는 쪽이다.
- **SKT·SK하이닉스 IT**: 프로그래머스형 4문제. 구현·자료구조·그래프가 중심. 삼성식 4시간 시뮬은 아니다.
- **LG전자**: 3문제 중 DFS/BFS 하나 + 구현 하나 패턴이 반복된다. 삼성 기출까지는 과하고, 프로그래머스 Lv.2~3 + 짧은 시뮬이면 된다.
- **LG CNS**: 2025 하 이후 공채는 코테가 없다. 인적성을 봐야 한다.
- **SK AX**: 2024부터 전통 알고리즘 코테 대신 AICT. 유형 문서는 참고만 하고, 생성형 AI로 구현·데이터 문제를 푸는 쪽을 본다.
